This guide shows how to put a Model Context Protocol (MCP) server behind the Smallstep MCP gateway.
When you finish, an AI agent on an enrolled device reaches the MCP server with the device's certificate.
The MCP client's configuration holds no API key.

The guide uses Linear as the example.
The steps are the same for the other MCP servers in the console's catalog.

[MCP Gateway](../platform/mcp-gateway.mdx) explains how the parts fit together.

## Before you begin

You will need:

- The MCP gateway turned on for your team.
- The Owner or Admin role in Smallstep.
- A device enrolled in Smallstep with the [Smallstep Agent](../platform/smallstep-agent.mdx) 0.70.0 or later.
  The device needs high assurance and a user assigned.
- An account with the MCP server's provider that can register an OAuth app.
  For Linear, that is a workspace admin.

# Step 1: Configure the gateway

The gateway accepts a device only when its certificate chains to your team's trust roots.
Set the trust roots once for the team.

## Download the root certificate

MCP server certificates come from your team's Accounts authority.

1. In Certificate Manager, go to [Authorities](https://smallstep.com/app/?next=/cm/authorities).
2. Select the Accounts authority.
3. Download the **Root Certificate**.

## Save the trust roots

1. In the Smallstep console, go to **Protect → MCP Gateway**.
2. Under **Device trust roots**, upload the root certificate.
   You can also paste its text.
3. If the file holds more than one certificate, the console asks you to pick one.
   Pick the certificate marked **Root**.
4. Choose **Save trust roots**.

The same page shows your team's **Gateway endpoint**.
Devices connect to this host.
You don't need to copy it, because the agent receives it with each MCP server you add.

# Step 2: Add an MCP server

The gateway forwards each request with the user's own OAuth access token.
To get those tokens, Smallstep needs an OAuth app that your team registers with the MCP server's provider.

## Start the form

1. In the Smallstep console, go to **Protect → MCP Proxies** and choose **Add MCP proxy**.
2. Under **Pick an MCP server**, choose **Linear**.
   The card fills in the name, the **Upstream** value, the MCP server's URL, and the provider's OAuth settings.
3. Under **Provider OAuth client**, copy the callback URL.

Keep the form open.

## Register an OAuth app

1. On the Linear card, follow **Register an OAuth app**.
   It opens the provider's page for new OAuth apps.
2. Create an app, and set its redirect or callback URL to the URL you copied.
3. Copy the app's client ID and client secret.

## Finish the form

1. Back in the Smallstep console, enter the **Client ID** and the **Client secret**.
2. Leave the other fields as the card set them.
3. Choose **Add MCP proxy**.

<Alert severity="warning" mb={4}>
  <div>
    Enter both the client ID and the client secret before you save.
    Without them, nobody can approve access to the MCP server.
    You can't edit an MCP server after you add it.
    To change a setting, delete the MCP server and add it again.
  </div>
</Alert>

Smallstep creates a credential for the MCP server.
The Smallstep Agent on each of your team's devices requests a certificate from it and keeps the certificate renewed.
A device can take a few minutes to receive a new MCP server.

Note the **Upstream** value, `linear` in this example.
Commands on the device use it to name the MCP server.

# Step 3: Configure clients

## Check that the device has its certificate

On an enrolled device, run:

```bash
step-agent status
```

The MCP server appears by name with a check mark once the agent has its certificate:

```text
Linear (mcp-linear) ✔
```

## Approve access to the MCP server

Each person approves access once for each MCP server.
On the device, run:

```bash
step-agent mcp tools list --upstream linear
```

The first time, the command stops and prints a link:

```text
consent required: open https://… to authorize this upstream
```

1. Open the link in a browser.
   The link is valid for 10 minutes.
2. Sign in to the provider and approve access for the OAuth app.
3. Run the command again.

If the link shows `this upstream is not configured for your tenant`, the MCP server has no OAuth client.
Delete it under **Protect → MCP Proxies** and add it again with the client ID and client secret.
