In this guide,
we'll talk about different approaches you can take
as you build your device inventory in Smallstep.

It's worth restating the overall goal of this process:
to build a high-assurance device inventory,
so that only your organization's devices
can access protected resources.

While many organizations
have device inventories in various locations
(IT Asset Management systems, device management platforms, etc),
these are not usually high-assurance inventories.
Smallstep uses hardware identifiers
and device attestation
to help you develop a high-assurance inventory
that can be the foundation for device authentication.

Here's a few ways to bring high-assurance device identifiers
into your Smallstep inventory:

### Manual self-enrollment

You can [manually invite users
to join your Smallstep team](https://smallstep.com/app/?next=/users/invite),
and they will be able to self-enroll devices
using the [Smallstep Agent](./smallstep-agent.mdx)'s `step-agent register` subcommand.

By default, administrators
must approve a new device
before it can access any of your resources.
You can change this in [Team Settings](https://smallstep.com/app/?next=/settings/team).

### IdP self-enrollment via SSO

This option requires IdP self-enrollment in [Team Settings](https://smallstep.com/app/?next=/settings/team) to be enabled.
It is disabled by default.

With IdP self-enrollment enabled,
when you connect Smallstep to your identity provider,
your users will be able to self-enroll
via single sign-on,
using the [Smallstep Agent](./smallstep-agent.mdx).

By default, administrators
must approve newly enrolled devices
before they can access any of your resources.
You can change this in [Team Settings](https://smallstep.com/app/?next=/settings/team).

### Sync Smallstep to an MDM

You can sync your existing MDM inventories into Smallstep.
Once an MDM is synced,
you can deploy the Smallstep Agent to your endpoints
to enable high-assurance protections.

Devices synced from an MDM inventory
are not automatically approved,
and they will not be marked as high-assurance
until Smallstep receives an attestation from the device.

For a concrete example,
see [Connect Jamf Pro to Smallstep](../tutorials/connect-jamf-pro-to-smallstep.mdx)

### Use osquery-based enrollment

For [Fleet-managed](../tutorials/connect-fleet-dm-to-smallstep.mdx) macOS, Linux, and Windows hosts, deploy the Smallstep osquery extension alongside the agent.
The osquery extension reports each device's identity to Fleet:
the TPM Endorsement Key on Linux and Windows,
and the serial number and agent attestation key on macOS.
Smallstep then syncs the data into your inventory.

### Add devices via API

You can import devices from any source into Smallstep using our API.

Use this when your devices are inventoried in a system that Smallstep can't sync from.

Devices added via API are automatically approved.
but they will not be marked as high-assurance
until Smallstep receives an attestation from the device.

You'll need [an API token](https://smallstep.com/app/?next=/settings/api/tokens/add) with all “device” scopes (put-device, patch-device, etc.).

Use the [Add Device](https://gateway.smallstep.com/v2026-05-01/operations/PostDevices) endpoint to create a device.
- For Apple devices, the `permanentIdentifier` must be the device's 9-character serial number.
- For TPM 2.0 devices, the `permanentIdentifier` must be the TPM Endorsement Key URI, in the format `urn:ek:sha256:ul3sYf6uQ6jVEXAMPLEXoAuHI10U8gTvEJ6bMj95LXI=`. (You can retrieve the EK URI by running `step agent tpm --fingerprint` on the device.)
- To create and assign a user to a device, fill in the `user` fields.

Once added,
the devices will be automatically approved.

You can see the device using the [List Devices](https://gateway.smallstep.com/v2026-05-01/operations/ListDevices) endpoint:

```bash
set +o history
echo "Authorization: Bearer [your API token]" > api_headers
set -o history
curl -sH @api_headers --request GET \
  --url https://gateway.smallstep.com/api/devices \
  --header 'Accept: application/json' \
  --header 'x-smallstep-api-version: 2026-05-01' | jq
```

You'll also see new devices in the Smallstep console,
under [Devices](https://smallstep.com/app/?next=/devices).

### Enroll devices with an enrollment token

Use a device enrollment token
when you build devices from an image or a launch template,
such as a pool of VMs or a render farm,
and want each one to enroll itself
without a user signing in
and without adding it to your inventory first.

One token enrolls any number of devices.
Every device enrolled with it gets the token's `device` attributes:
its tags, metadata, ownership, and whether it is shared.
Tags and metadata are added to any the device already has.

Devices enrolled with a token
follow the approval settings in [Team Settings](https://smallstep.com/app/?next=/settings/team),
like any other device the agent enrolls.

#### Create a token

You'll need [an API token](https://smallstep.com/app/?next=/settings/api/tokens/add) with the device enrollment token scopes
(post-device-enrollment-tokens, list-device-enrollment-tokens, get-device-enrollment-token, and delete-device-enrollment-token).

Use the [Create Device Enrollment Token](https://gateway.smallstep.com/v2026-05-01/operations/post-device-enrollment-tokens) endpoint:

```bash
set +o history
echo "Authorization: Bearer [your API token]" > api_headers
set -o history
curl -sH @api_headers --request POST \
  --url https://gateway.smallstep.com/api/device-enrollment-tokens \
  --header 'Content-Type: application/json' \
  --header 'x-smallstep-api-version: 2026-05-01' \
  --data '{
    "title": "render-pool-a",
    "expiresAt": "2027-06-30T00:00:00Z",
    "device": {
      "tags": ["render-farm"],
      "ownership": "company",
      "shared": true,
      "metadata": { "pool": "render-a" }
    }
  }' | jq
```

The response includes the token's `secret`.
It's returned only when the token is created, so store it somewhere safe, such as your secrets manager.
If you lose it, create a new token.

If you omit `expiresAt`, the token expires in 10 years, the maximum.

You can also manage tokens with Terraform,
using the `smallstep_device_enrollment_token` resource
in the [Smallstep Terraform provider](https://registry.terraform.io/providers/smallstep/smallstep/latest/docs).
The resource's `secret` attribute holds the secret.

#### Enroll a device

On each device, write the secret to a file and register the device once:

```bash
sudo step-agent register [team name] --token-file /path/to/token
```

`--token-file` keeps the secret out of your shell history and the process list.
You can pass it with `--token` instead.
Then [start the agent](./smallstep-agent.mdx#start-the-agent) as usual.
`register` saves the agent's configuration, so `start` doesn't need the token.

On macOS, add `--save-managed-config`,
so the agent's launch agent can read the configuration:

```bash
/Applications/SmallstepAgent.app/Contents/MacOS/SmallstepAgent register <team-slug> --token-file /path/to/token --save-managed-config
```

#### Keep the token safe

Treat the secret like a password:
anyone who holds it can enroll devices into your team until it expires or is deleted.
Use a separate token for each pool of devices,
so you can delete one without affecting the others.
The token's `device` attributes can be read by anyone who holds the secret,
so don't put secrets in `metadata`.

#### Monitor and delete tokens

[List Device Enrollment Tokens](https://gateway.smallstep.com/v2026-05-01/operations/list-device-enrollment-tokens)
shows each token's `status`, `useCount` (the number of new devices it enrolled), and `lastUsedAt`.
A device enrolled with a token shows the token's ID in its `enrollmentTokenID`.

To stop a token from enrolling devices,
delete it with [Delete Device Enrollment Token](https://gateway.smallstep.com/v2026-05-01/operations/delete-device-enrollment-token).
This takes effect immediately.
Devices that have already enrolled with the token keep working;
remove them from your inventory if they should lose access too.
